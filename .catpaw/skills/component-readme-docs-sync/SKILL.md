# Component README to Docs Sync

## When to apply

Apply this workflow whenever a README is created or changed under:

`packages/components/src/components/**/README.md`

This skill covers component documentation only. Utility and event README files are not copied unless the user explicitly requests them.

## Target mapping

Copy the component README content to the matching Markdown page in:

`packages/docs/public/docs/components/`

For a standard component directory, remove the repeated component directory level and change the extension to `.md`:

| Component README                                                 | Docs page                                                   |
| ---------------------------------------------------------------- | ----------------------------------------------------------- |
| `packages/components/src/components/basic/Icon/README.md`        | `packages/docs/public/docs/components/basic/Icon.md`        |
| `packages/components/src/components/form/FormText/README.md`     | `packages/docs/public/docs/components/form/FormText.md`     |
| `packages/components/src/components/theme/ThemeToggle/README.md` | `packages/docs/public/docs/components/theme/ThemeToggle.md` |

The target path must match the path generated by `packages/docs/scripts/init.py` for the component's Vue source. Do not write to `packages/docs/dist/`.

## Workflow

1. Read the changed component README and its `.vue` and `type.ts` files.
2. Find the documentation page using the target mapping.
3. Create the target page if it does not exist; otherwise replace its API documentation with the README content.
4. Preserve or add only documentation-site content that is necessary for rendering, such as a component title or usage link. Do not retain stale Props, Emits, Slots, or Exposes tables from the previous page.
5. Ensure the synced page accurately includes the component purpose, basic usage, Props, Emits, Slots, and Exposes. Categories unavailable in the component must remain explicitly marked as “无”.
6. Keep source README as the canonical API documentation. When source and docs differ, update the docs page to match source rather than editing the README to fit an outdated docs page.

## Special cases

- If a README documents multiple directly exported components, synchronize its relevant sections to every matching generated docs page. For example, `loading/animations/README.md` must be split or adapted for `Breathing.md`, `Spinner.md`, and `Skeleton.md` so each page documents its own component.
- If the docs page has a display demo under `packages/docs/src/display/`, do not modify the demo unless the README's usage example is demonstrably stale or incompatible with the component API.
- If the mapping is ambiguous, inspect `packages/docs/scripts/init.py` and the Vue source path before editing. Do not guess paths.

## Verification

Before completing the change:

1. Confirm every changed component README has a corresponding page under `packages/docs/public/docs/components/`.
2. Compare the component API sections in both files; names, types, defaults, events, slots, and exposed methods must match.
3. Confirm no generated output in `packages/docs/dist/` was changed.
4. Run the relevant docs check or build when the task scope requires validation.
