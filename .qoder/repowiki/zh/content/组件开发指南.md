# 组件开发指南

## 组件文件结构

每个组件遵循统一的**四文件 + 测试**模式：

```
src/components/{category}/{ComponentName}/
├── ComponentName.vue     # Vue SFC（Q 前缀，如 QIcon.vue）
├── composable.ts         # 业务逻辑 / 组合式函数
├── type.ts               # TypeScript 接口 & Props 类型
├── index.ts              # 重导出（export * from + 默认导出）
└── __test__/
    └── composable.test.ts # Vitest 内联测试
```

**代码来源**: [packages/components/src/components/basic/Icon/index.ts](file://packages/components/src/components/basic/Icon/index.ts) · [basic/Icon/composable.ts](file://packages/components/src/components/basic/Icon/composable.ts) · [basic/Icon/type.ts](file://packages/components/src/components/basic/Icon/type.ts)

### index.ts 约定

```typescript
export * from './composable';
export * from './type';
export { default as QIcon } from './Icon.vue';
```

### 视图与逻辑分离

- `.vue` 文件：仅包含模板和样式，逻辑委托给 composable
- `composable.ts`：包含所有业务逻辑、响应式状态、方法，命名为 `use{ComponentName}`
- `type.ts`：定义 Props 接口、emit 类型和组件相关类型导出

## 新增组件步骤

1. 在对应分类目录下创建组件文件夹，遵循四文件 + 测试结构
2. 运行 `pnpm run update`（在 components 或 docs 包中）自动更新入口文件和文档
3. 所有组件使用 `Q` 前缀命名

## 编码规范

### 函数规范

- **命名**：严格驼峰命名（camelCase）
- **注释**：必须包含完整的 JSDoc 注释，包括 `@param`、`@returns`、`@throws`
- **导出控制**：仅导出必须暴露的公共接口，隐藏内部实现细节

### 通用原则

- **高内聚低耦合**：遵循 SOLID 设计原则
- **代码精炼**：避免冗余逻辑，拒绝过度设计
- **导入导出干净**：严格管控导出内容，确保需要被外部调用的核心内容均已正确导出

## 表单组件约定

所有表单组件共享统一的 Props 和 Emits 接口：

**Props** (`FormComponentProps<T>`)：modelValue, name, label, disabled, readonly, size, status, required, placeholder, clearable, autofocus, id, direction, errorMessage

**Emits** (`FormComponentEmits<T>`)：update:modelValue, change, focus, blur, input, clear
